Description and outcomes

This course studies the operating system as a manager of CPU, memory, files, disks, and devices. Topics include processes, threads, scheduling, virtual memory, synchronization, deadlock, I/O, and file systems, with hands-on C and teaching-OS work.

  1. Explain OS abstractions, mechanisms, and policies.
  2. Analyze scheduling, translation, replacement, and file-system traces.
  3. Identify races, invariants, synchronization requirements, and liveness risks.
  4. Build, modify, test, and explain basic components in a reproducible environment.
  5. Communicate design decisions, evidence, limitations, and contributions.

Support routes for recurring barriers

  • Run the environment check before assessed work. The common container supplies C, pthreads, Make, Python, GDB, Valgrind, strace, and QEMU; Docker itself remains an explicit prerequisite.
  • Apple-silicon and other hosts can use the headless linux/amd64 xv6 preflight instead of a graphical QEMU window. The PA1A reference checks both CPU start messages, init: starting sh, and an interactive marker.
  • Use the clean pinned clone when a downloaded archive or nested extraction is ambiguous. It verifies the official source commit and refuses to overwrite an existing target.
  • Before xv6 or pthread work, complete the mapped smaller lab, state invariants and an expected trace, and run the solution-free preflight. A pass is formative feedback, not an official evaluation.
  • Follow the current Canvas rubric for evidence and reopen the submission receipt and files. A local folder, screenshot, or passing preflight is not a Canvas submission.
