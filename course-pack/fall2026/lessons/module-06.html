Demand Paging and Replacement

Learning objectives

  • Trace a page fault from trap to restart.
  • Compare FIFO, OPT, LRU, and Clock.
  • Reason about locality and thrashing.

Read before class

  1. Chapter 21: Swapping: Mechanisms
    Read for: Present bits, page faults, swap space, page-in/page-out, and restart.
  2. Chapter 22: Swapping: Policies
    Read for: OPT, FIFO, LRU approximations, Clock, locality, and thrashing.

Demand paging leaves some virtual pages outside physical memory. Accessing a nonresident valid page traps to the OS, which locates data, chooses a frame, performs I/O if needed, updates metadata, and restarts the instruction.

Replacement policy decides which resident page to evict. OPT is an unattainable benchmark, LRU exploits recency, FIFO is simple, and Clock approximates recency with reference bits.

Locality makes caching effective. When a workload's actively used pages exceed available memory, repeated eviction and reload can cause thrashing.

Worked three-frame trace for references 0,1,2,0,1,3,0,3,1,2,1: FIFO records seven misses and four hits because it evicts page 0 at reference 3 and later pays for ignoring recent use. LRU records five misses and six hits by evicting stale page 2 instead, so the following reference to 0 hits.

OPT also has five misses on this particular string, so LRU ties the unattainable lower bound here without becoming optimal in general. The first three compulsory misses cannot be avoided. Always report both the reference string and frame count with a hit rate; changing either changes the result.

Readiness questions with explanations

Understand What distinguishes a page fault from a TLB miss?
  1. A page fault means the referenced page is not currently resident or access is invalid
  2. A TLB miss always terminates the process
  3. A page fault never enters the kernel
  4. They are identical

Answer: A. A TLB miss concerns the translation cache; a page fault concerns page-table validity/residency or protection.

Source: OSTEP Chapter 21: Swapping Mechanisms

Remember Why is OPT mainly a benchmark?
  1. It requires future references
  2. It cannot count faults
  3. It uses no memory
  4. It is identical to FIFO

Answer: A. OPT evicts the page whose next use is farthest in the future, information a real system does not possess.

Source: OSTEP Chapter 22: Swapping Policies

Analyze What pattern best signals thrashing?
  1. High CPU use and no faults
  2. Frequent faults with little useful execution
  3. One compulsory miss at startup
  4. A large TLB

Answer: B. Thrashing spends much of the time moving pages rather than running useful instructions.

Source: OSTEP Chapters 21–22: Beyond Physical Memory and Replacement

Remember Which bit helps Clock approximate recent use?
  1. Reference/use bit
  2. Executable filename bit
  3. PID parity bit
  4. Directory link count

Hint: The hardware records whether the page was accessed.

Answer: A. Clock examines and clears a reference bit to give recently used pages another chance.

Source: OSTEP Chapter 22: Replacement Policy

Understand Why may a dirty victim page cost more to evict than a clean one?
  1. It may require a write before reuse of the frame
  2. It has no virtual address
  3. It cannot be referenced
  4. It is always executable

Hint: Clean data already has an up-to-date backing copy.

Answer: A. Modified data must be preserved to backing storage before its frame is repurposed.

Source: OSTEP Chapters 21–22

Apply Frames contain A, B, C in FIFO order, and D misses. Which page does FIFO evict?
  1. A
  2. B
  3. C
  4. D

Hint: FIFO ignores recent access and uses arrival order.

Answer: A. FIFO removes the page that entered memory earliest, which is A.

Source: OSTEP Chapter 22: Replacement Policy

Analyze Why can adding memory sometimes increase FIFO faults on a particular trace?
  1. Belady’s anomaly
  2. DMA coherence
  3. Priority inheritance
  4. Write-ahead logging

Hint: This counterintuitive behavior is associated with FIFO.

Answer: A. FIFO lacks the stack property and can exhibit Belady’s anomaly.

Source: OSTEP Chapter 22: Replacement Policy

Evaluate Which experiment best supports a replacement-policy conclusion?
  1. One trace with no frame count
  2. Multiple traces and frame counts with fault tables and locality interpretation
  3. Policy names only
  4. A compiler warning

Hint: Avoid claiming a universal winner from one unexplained run.

Answer: B. Replacement behavior depends on trace locality and available frames, so both must be varied and reported.
