I/O Devices and Device Interaction

Learning objectives

  • Explain polling, interrupts, and DMA.
  • Trace an I/O request across user/kernel/device boundaries.
  • Recognize why device latency changes OS policy.

Read before class

  1. Chapter 36: I/O Devices
    Read for: Device registers, polling, interrupts, DMA, drivers, and the I/O software stack.

Programs access devices through OS abstractions and system calls. The kernel validates requests, coordinates drivers, and arranges data transfer while preserving isolation.

Polling repeatedly checks device status; interrupts let the CPU do other work until notification; DMA moves bulk data between device and memory with limited CPU copying. Each approach has workload-dependent overheads.

A correct I/O trace distinguishes request submission, waiting/blocking, device completion, interrupt handling, and process wakeup.

Worked 4 KiB read comparison: for a device taking 10 ms on a 1 GHz CPU, polling with programmed I/O can consume roughly ten million wait cycles plus a CPU copy loop. Interrupts avoid the busy wait but still leave the copy to the CPU; interrupts with DMA reduce CPU work to transfer setup and completion handling. Interrupts address waiting, while DMA addresses copying.

A system-call trace proves a kernel crossing, not necessarily a physical device access. openat may resolve metadata, read may be satisfied by the buffer cache, read returning 0 means end of file, and close releases the descriptor. Descriptor 3 is commonly first because 0, 1, and 2 are standard input, output, and error.

Hands-on practice

Use `strace` in the container to observe open/read/write calls from a small C program; annotate which operations cross into the kernel.

Evidence artifact: Filtered trace, annotated request path, and one performance hypothesis.

Trace the I/O path

  1. Predict which open/write/fsync/close calls the program will make.
    Evidence: An ordered call list.
  2. Run normally and inspect the resulting file.
    Evidence: Program output and file content.
  3. Run the documented strace filter.
    Evidence: A short trace with return values.
  4. Mark user/kernel crossings and blocking possibilities.
    Evidence: An annotated request path.
  5. Explain where polling, interrupt, or DMA could appear below the system-call view.
    Evidence: A layered diagram with stated inference.

Readiness questions with explanations

Understand What is a principal benefit of DMA?
  1. It removes files
  2. It transfers bulk data without CPU copying every word
  3. It prevents all interrupts
  4. It replaces virtual memory

Answer: B. The CPU programs the transfer, and the DMA engine handles much of the data movement.

Source: OSTEP Chapter 36: I/O Devices

Analyze When can polling be reasonable?
  1. A device is expected to complete almost immediately
  2. A device takes minutes and CPU work is plentiful
  3. There is no status register
  4. The process has exited

Answer: A. For very short waits, polling can cost less than sleeping and handling an interrupt.

Apply Which tool can show a Linux program's file-related system calls?
  1. strace
  2. make clean only
  3. A page-table simulator
  4. The linker alone

Answer: A. strace records system-call entry, arguments, and results, making the user/kernel boundary visible.

Remember What usually notifies the CPU that an asynchronous device operation completed?
  1. Interrupt
  2. Page offset
  3. Hard link
  4. Mutex owner

Hint: The CPU need not poll continuously.

Answer: A. Devices commonly raise interrupts so the kernel can handle completion.

Understand Why does a process often block during slow I/O?
  1. The CPU can run other ready work while the device progresses
  2. Blocking makes the device instantaneous
  3. It removes the driver
  4. It converts the file to memory

Hint: Separate CPU service from device latency.

Answer: A. Blocking avoids spending CPU cycles on a request that cannot yet complete.

  1. read(3, buffer, 64) = 12
  2. counter++
  3. int x;
  4. a source-code comment

Hint: Look for a system-call name and result.

Answer: A. strace records the read system call, descriptor, requested bytes, and return value.

Analyze Why can interrupts outperform polling for a slow unpredictable device?
  1. The CPU can perform other work until completion notification
  2. Interrupts eliminate driver code
  3. Polling has no status checks
  4. DMA requires polling forever

Hint: Compare useful CPU work during the wait.

Answer: A. Interrupts avoid repeated checks during a long or uncertain wait.

Source: OSTEP Chapter 36; lecture 3-1

Evaluate Which claim about DMA is appropriately bounded?
  1. DMA reduces CPU involvement in bulk transfer but setup and completion handling still cost work
  2. DMA makes I/O free
  3. DMA removes memory
  4. DMA prevents every interrupt

Hint: Avoid an absolute performance claim.

Answer: A. DMA changes who moves data; it does not eliminate setup, coordination, or completion costs.
