CPU Mechanisms and Scheduling

Learning objectives

  • Compute turnaround, response, and waiting time.

Limited direct execution lets user code run directly on the CPU while privileged operations trap into the kernel. A periodic timer interrupt ensures the OS can regain control even when a process does not cooperate.

Schedulers balance different goals. Turnaround time measures completion latency, response time measures time until first run, and fairness concerns how service is shared. A policy that optimizes one workload can harm another.

MLFQ approximates knowledge of job behavior by observing CPU use. Interactive jobs tend to remain at higher priority; CPU-intensive jobs move downward. Priority boosts prevent indefinite starvation.

Worked turnaround comparison: if A needs 100 seconds and B and C need 10 seconds each, all arriving at time 0, FIFO order A-B-C completes them at 100, 110, and 120 for average turnaround 110. SJF order B-C-A completes them at 10, 20, and 120 for average 50, avoiding the convoy effect.

Worked response comparison: for three five-second jobs arriving together, non-preemptive SJF first runs A, B, and C at times 0, 5, and 10, for average response 5. Round robin with a one-second quantum first runs them at 0, 1, and 2, for average response 1, while increasing completion time and adding context-switch overhead. State the workload, metric, and quantum before calling one policy better.

Readiness questions with explanations

Understand Why does an OS need a timer interrupt?
  1. To allocate disk blocks
  2. To regain CPU control from a running process
  3. To translate addresses
  4. To create a file descriptor

Answer: B. The timer provides a non-cooperative path back into the kernel so the scheduler can preempt.

Source: OSTEP Chapter 6: Limited Direct Execution

Apply Jobs A(3) and B(1) arrive together. Under non-preemptive SJF, which order minimizes average turnaround?
  1. A then B
  2. B then A
  3. Either is identical
  4. They must alternate

Answer: B. Running the shortest job first completes B at 1 and A at 4, reducing average completion time.

Source: OSTEP Chapter 7: Scheduling Introduction

Analyze What MLFQ mechanism primarily addresses starvation?
  1. Longer process names
  2. Periodic priority boosts
  3. Disabling preemption
  4. One global time quantum only

Answer: B. Boosting waiting jobs returns them to a higher-priority queue so they eventually receive service.

Source: OSTEP Chapter 8: Multi-Level Feedback Queue

Remember Response time measures what interval?
  1. Arrival to first run
  2. Arrival to completion
  3. First run to disk flush
  4. Context switch to page fault

Hint: Interactive users notice the first visible service.

Answer: A. Response time is the delay from arrival until the job first receives CPU service.

Source: OSTEP Chapters 7–10: CPU Scheduling

Understand Why can FCFS exhibit a convoy effect?
  1. A long job can delay many short jobs behind it
  2. It always preempts too often
  3. It predicts future bursts exactly
  4. It runs no jobs

Hint: Picture one long checkout followed by many short ones.

Answer: A. A long non-preemptive job at the front makes short arrivals wait.

Source: OSTEP Chapter 7: Scheduling Introduction

Apply Lottery-scheduled job A owns 75 tickets and B owns 25. Over many draws, what service share is expected?
  1. A about 75% and B about 25%
  2. Each exactly 50%
  3. A always 100%
  4. Ticket counts affect only memory

Hint: Convert each ticket count to a fraction of the 100-ticket total.

Answer: A. Lottery scheduling makes each ticket equally likely, so long-run service is proportional to 75:25, while short runs can vary.

Source: OSTEP Chapter 9: Proportional Share

Analyze Why can moving a process between CPUs reduce performance even when both CPUs are idle enough?
  1. The process may lose warm cache state and incur migration cost
  2. A process can never run on another CPU
  3. Migration removes its virtual address space
  4. It disables timer interrupts

Hint: Consider what hardware state is local to one CPU.

Answer: A. Multiprocessor scheduling balances load against cache affinity; migration can discard useful per-CPU cache locality.

Source: OSTEP Chapter 10: Multiprocessor Scheduling

Evaluate Which evidence is sufficient to compare two schedulers on one workload?
  1. Policy names alone
  2. Arrival/burst assumptions, Gantt traces, computed metrics, and stated objective
  3. One unexplained average
  4. The source-code line count

Hint: Choose evidence that makes the conclusion reproducible.

Answer: B. A defensible comparison exposes inputs, execution, metric arithmetic, and the goal being optimized.
