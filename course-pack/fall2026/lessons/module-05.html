Paging, TLBs, and Page Tables

Learning objectives

  • Split a virtual address into VPN and offset.
  • Explain TLB hits and misses.
  • Compare linear and multi-level page tables.

Read before class

  1. Chapter 18: Paging: Introduction
    Read for: Pages, frames, VPN/offset decomposition, PTEs, and page-table cost.
  2. Chapter 19: Translation Lookaside Buffers
    Read for: TLB hits and misses, context switches, replacement, and correctness.
  3. Chapter 20: Advanced Page Tables
    Read for: Larger pages, hybrids, and multi-level page-table space/time tradeoffs.

Paging divides virtual and physical memory into fixed-size pages and frames. The offset is preserved during translation; a page-table entry supplies the physical frame number and protection metadata.

A translation lookaside buffer caches recent translations. A TLB hit avoids a page-table lookup, while a TLB miss invokes hardware or OS-assisted page-table traversal. A TLB miss is not automatically a page fault.

Linear page tables are simple but can consume substantial memory. Multi-level tables allocate lower levels only for populated virtual regions, trading extra lookup steps for space savings.

Readiness questions with explanations

Apply With 4 KiB pages, how many offset bits are in a byte address?
  1. 4
  2. 10
  3. 12
  4. 16

Answer: C. 4 KiB is 4096 = 2^12 bytes, so the offset uses 12 bits.

Source: OSTEP Chapters 18–20: Paging, TLBs, and Page Tables

Understand Which statement is correct?
  1. Every TLB miss is a page fault
  2. A TLB caches virtual-to-physical translations
  3. The page offset changes during translation
  4. Paging creates external fragmentation between frames

Answer: B. A TLB is a translation cache. Missing there may still find a valid in-memory page-table entry.

Source: OSTEP Chapters 18–20: Paging, TLBs, and Page Tables

Analyze Why can a multi-level page table use less memory?
  1. It removes offsets
  2. It omits lower-level tables for unused regions
  3. It stores pages on the CPU
  4. It disables protection bits

Answer: B. Sparse address spaces need only the page-table subtrees that describe mapped regions.

Source: OSTEP Chapters 18–20: Paging, TLBs, and Page Tables

Remember Which virtual-address field remains unchanged through paging translation?
  1. VPN
  2. Page offset
  3. PFN
  4. Valid bit

Hint: Position within the page is the same within the frame.

Answer: B. Translation replaces the virtual page number with a physical frame number and preserves the offset.

Source: OSTEP Chapter 18: Paging

Understand What information does a valid page-table entry normally provide?
  1. A physical frame and access metadata
  2. A process arrival time
  3. A directory pathname only
  4. A CPU burst prediction

Hint: It supports both translation and protection.

Answer: A. The PTE maps a VPN to a PFN and includes bits such as valid, writable, or referenced.

Source: OSTEP Chapters 18–20

Apply For 1 KiB pages, how many low-order offset bits does an address have?
  1. 8
  2. 10
  3. 12
  4. 16

Hint: Express the page size as a power of two.

Answer: B. 1 KiB is 1024 bytes, or 2^10, so ten bits select a byte within the page.

Source: OSTEP Chapter 18: Paging

Analyze A TLB miss finds a valid resident PTE. What happens next conceptually?
  1. The translation is installed and access can retry
  2. The process must always terminate
  3. The disk is reformatted
  4. The page offset is discarded

Hint: A cache miss does not imply the data is absent from memory.

Answer: A. The system completes page-table lookup, caches the translation, and retries without a disk page-in.

Source: OSTEP Chapter 19: TLBs

Evaluate Which design best fits a very sparse virtual address space?
  1. A fully allocated linear table regardless of use
  2. A multi-level table that omits empty subtrees
  3. No translation protection
  4. One TLB entry per byte

Hint: Optimize metadata space for large unused regions.

Answer: B. Multi-level tables trade extra walks for allocating page-table structures only where mappings exist.
