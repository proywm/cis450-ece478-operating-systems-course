Concurrency · Module 10

Deadlock and Liveness

Learning objectives

  • Identify the four Coffman conditions.
  • Draw a wait-for graph.
  • Compare prevention, avoidance, detection, and recovery.

Read before class

  1. Chapter 32: Common Concurrency Problems
    Read for: Atomicity/order violations, deadlock conditions, prevention, avoidance, detection, and liveness.

Deadlock is a liveness failure in which participants wait forever for resources held within the waiting set. The classic necessary conditions are mutual exclusion, hold-and-wait, no preemption, and circular wait.

A consistent global lock order prevents cycles. Other strategies remove a different necessary condition, avoid unsafe allocations, detect cycles after they form, or recover by terminating or rolling back work.

Not every hang is deadlock. Starvation denies service to one participant while the system still progresses; livelock changes state repeatedly without useful progress.

Hands-on practice

Create a two-lock deadlock under controlled conditions, capture thread stacks, then repair it with a documented lock order.

Evidence artifact: Wait-for graph, stack evidence, fixed code, and a deadlock/starvation/livelock comparison.

Diagnose lock ordering safely

  1. Translate the provided acquisition sequences into a wait-for graph.
    Evidence: A labeled graph.
  2. Identify the four necessary deadlock conditions in the scenario.
    Evidence: A condition-to-evidence table.
  3. Run the finite graph-cycle checker.
    Evidence: The detected cycle.
  4. Rewrite both sequences to follow one global order.
    Evidence: Cycle-free checker output.
  5. Contrast deadlock, starvation, and livelock.
    Evidence: One observable signature for each.

  1. Deadlock necessarily
  2. Starvation
  3. A page fault
  4. Journaling

Answer: B. Progress by others with indefinite denial to one participant is starvation.

Understand How does a global lock order prevent deadlock?
  1. It prevents cycles in acquisition dependencies
  2. It removes mutual exclusion
  3. It guarantees fairness
  4. It disables waiting

Hint: A cycle would require an order contradiction.

Answer: A. If every thread follows one strict order, a circular wait cannot form.

Apply T1 holds A and waits for B; T2 holds B and waits for A. What graph evidence exists?
  1. A wait-for cycle
  2. A TLB hit
  3. A journal commit
  4. A clean shutdown

Hint: Draw who waits for whom.

Answer: A. T1→T2 and T2→T1 form a cycle consistent with deadlock.

Analyze Two threads repeatedly release and reacquire in response to each other but finish no work. What is this?
  1. Livelock
  2. Starvation only
  3. Demand paging
  4. Journaling

Hint: Unlike deadlock, the participants are not simply blocked.

Answer: A. They remain active and change state but make no useful progress.
