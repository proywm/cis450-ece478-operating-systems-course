Processes and Process APIs

Learning objectives

  • Describe process state and address-space contents.
  • Trace fork, exec, wait, and exit.
  • Explain how a shell builds a process pipeline.

Read before class

  1. Chapter 4: The Abstraction: The Process
    Read for: Process state, process lists, and transitions among running, ready, and blocked.
  2. Chapter 5: Interlude: Process API
    Read for: fork, wait, exec, process control, and how a shell uses the API.

A process is a running program plus the state needed to resume it: address space, registers, open-file information, credentials, and scheduling state. The operating system assigns a process identifier and tracks transitions such as ready, running, and blocked.

fork creates a child process with a logically separate address space; its return value distinguishes parent from child. exec replaces the calling process image with another program. wait lets a parent synchronize with child termination, and exit releases the process.

The separation of fork and exec gives a shell a useful setup window: after fork and before exec, the child can redirect file descriptors or construct a pipeline.

Readiness questions with explanations

Remember What does fork return in the newly created child?
  1. The parent PID
  2. Zero
  3. Negative one
  4. The child PID

Answer: B. A successful fork returns zero in the child and the child PID in the parent.

Source: OSTEP Chapters 4–5: Processes and Process API

Understand What does exec do to the calling process?
  1. Creates a second process
  2. Replaces its program image
  3. Blocks until a child exits
  4. Duplicates every open file

Answer: B. exec loads a new program into the current process; it does not create another process.

Source: OSTEP Chapters 4–5: Processes and Process API

Analyze Why is fork followed by exec useful to a shell?
  1. The parent can change the child after exec
  2. The child can set redirection before replacing its image
  3. exec automatically waits
  4. fork prevents context switches

Answer: B. The child configures descriptors and environment between fork and exec, enabling redirection and pipelines.

Source: OSTEP Chapters 4–5: Processes and Process API

Remember Which call lets a parent collect a terminated child?
  1. exec
  2. wait
  3. open
  4. mmap

Hint: The parent uses this after fork.

Answer: B. wait or waitpid synchronizes with child termination and collects its status.

Source: OSTEP Chapter 5: Process API

Understand After a successful fork, why can parent and child print different PID values?
  1. They are different processes with distinct identities
  2. fork disables identifiers
  3. exec already ran
  4. They share one stack pointer forever

Hint: Separate address spaces do not imply the same identity.

Answer: A. The child begins from copied logical state but is a separately identified process.

Source: OSTEP Chapter 5: Process API

Apply A parent must print only after its child exits. Which change directly enforces this order?
  1. Add wait in the parent
  2. Call fork twice
  3. Remove exit
  4. Increase the child PID

Hint: Use explicit synchronization, not timing.

Answer: A. wait blocks the parent until a child changes to a collectable state.

Source: OSTEP Chapter 5: Process API

Analyze Why can output order vary when parent and child both print immediately after fork?
  1. The file contents select the order
  2. The scheduler may run either ready process first
  3. fork sorts output alphabetically
  4. Both prints are one atomic instruction

Hint: No wait or other ordering edge has been established.

Answer: B. Both processes are runnable and their execution order is a scheduling decision.
