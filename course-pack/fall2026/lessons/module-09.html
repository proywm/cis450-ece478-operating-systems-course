Condition Variables and Semaphores

Learning objectives

  • Use condition variables with a predicate and mutex.
  • Distinguish mutual exclusion from condition synchronization.
  • Model counting and binary semaphores.

Read before class

  1. Chapter 30: Condition Variables
    Read for: Predicates, wait/signal, Mesa semantics, producer/consumer, and covering conditions.
  2. Chapter 31: Semaphores
    Read for: Binary/counting semaphores, ordering, bounded buffers, readers/writers, and dining philosophers.

A condition variable lets a thread sleep until shared state may satisfy a predicate. The thread checks that predicate while holding the associated mutex and waits in a loop because wakeups do not guarantee the condition is now true.

A semaphore combines a counter with atomic wait and post operations. A counting semaphore can represent available units of a resource; a binary semaphore can resemble a lock, though ownership conventions differ.

Correct synchronization begins with state and invariants, not with choosing a primitive. First state what must be true; then choose locks, conditions, or semaphores that enforce it.

Worked condition-variable trace: two consumers wait while count is zero. A producer adds one item and signals; the first consumer wakes and consumes it. If the second consumer also wakes, an if guard lets it continue with count still zero, but a while guard rechecks the predicate under the mutex and waits again. A signal means the condition may hold, not that ownership has transferred.

Semaphore initial values express intent: 1 supports binary exclusion, 0 makes a waiter block until another thread posts for ordering, and N represents N available identical resources. Choosing 0 when lock-like behavior requires 1 produces immediate deadlock.

Readiness questions with explanations

Apply How should a condition-variable wait normally be guarded?
  1. By an if with no lock
  2. By a while loop checking the predicate under the mutex
  3. By sleeping for a fixed time
  4. By a page fault

Answer: B. The predicate must be rechecked after wakeup while the mutex protects the shared state.

Understand What can a counting semaphore represent?
  1. Only a Boolean
  2. The number of available identical resources
  3. A virtual address
  4. A process identifier

Answer: B. Its count can track multiple available units; wait consumes one and post returns one.

Analyze Why is a timed sleep a weak substitute for synchronization?
  1. Time never advances
  2. It guesses about another thread rather than observing protected state
  3. It always deadlocks
  4. It prevents compilation

Answer: B. Timing varies across executions; synchronization must encode the actual condition or ordering.

Source: OSTEP Chapters 30–31: Condition Variables and Semaphores

Remember Which operation increments a semaphore and may wake a waiter?
  1. post
  2. wait
  3. fork
  4. exec

Hint: This is sometimes called V.

Answer: A. sem_post returns a unit and can unblock a waiting thread.

Understand Why must condition-variable code test a predicate rather than treat a signal as stored state?
  1. The predicate describes the actual protected state; a signal is only a notification
  2. Signals write the file system
  3. Predicates disable mutexes
  4. A signal always counts resources

Hint: Ask what remains true if wakeups are early or shared.

Answer: A. Correctness depends on state under the mutex, and wakeups only prompt rechecking.

Source: OSTEP Chapter 30; lecture 2-3

Apply A buffer has capacity 4 and currently 0 items. What should a consumer do?
  1. Wait in a loop until count > 0 while using the mutex/condition
  2. Read slot 0 immediately
  3. Sleep one second and assume success
  4. Increment capacity

Hint: Express the condition on buffer state.

Answer: A. The consumer cannot remove an item until the protected nonempty predicate holds.

Analyze Why is signaling a condition while changing its predicate without the mutex risky?
  1. A waiter can miss or observe an inconsistent state transition
  2. It makes the semaphore negative by definition
  3. It changes virtual addresses
  4. It forces DMA

Hint: Reason about the check-to-sleep race.

Answer: A. Predicate changes and notification need a consistent synchronization protocol.

Evaluate For a pool of three identical resources, which starting primitive best models availability?
  1. Counting semaphore initialized to 3
  2. Condition variable with no predicate or mutex
  3. Unlocked Boolean
  4. Timer interrupt

Hint: Choose a primitive whose state is a resource count.

Answer: A. The count directly represents three available units and wait/post acquire/release one.
